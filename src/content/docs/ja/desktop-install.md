`v0.4.1` から独立したデスクトップ版を提供しています。実行環境を内蔵し、Node.js、Docker、データベースの別途インストールは不要です。AI は任意設定で、モデルは同梱しません。

## ダウンロードとインストール

| システム | インストーラー | 手順 |
| --- | --- | --- |
| Windows x64 | [EXE](https://github.com/Pls-1q43/Dibao/releases/download/v0.4.1/Dibao-0.4.1-win-x64.exe) | 現在のユーザー用にインストーラーを実行します。 |
| Intel Mac | [x64 DMG](https://github.com/Pls-1q43/Dibao/releases/download/v0.4.1/Dibao-0.4.1-mac-x64.dmg) | DMG を開き、Dibao を「アプリケーション」へ移します。 |
| Apple Silicon Mac | [arm64 DMG](https://github.com/Pls-1q43/Dibao/releases/download/v0.4.1/Dibao-0.4.1-mac-arm64.dmg) | DMG を開き、Dibao を「アプリケーション」へ移します。 |

[GitHub Release](https://github.com/Pls-1q43/Dibao/releases/tag/v0.4.1) から直接取得でき、Actions の外側 ZIP は不要です。

現在のパッケージは未署名です。Windows では不明な発行元の警告、macOS では初回起動の制限が出る場合があります。公式 Release のみを使用し、macOS では「システム設定 → プライバシーとセキュリティ」で確認してください。システムの安全確認を無効にしないでください。組織の管理ポリシーにより起動できない場合もあります。

## 初回設定

1. 起動後、歓迎画面で日本語、中文、English から言語を選びます。
2. この PC の所有者アカウントとパスワードを作成します。
3. RSS / Atom または OPML を追加します。「あとで追加」でスキップもできます。
4. 必要に応じて [Provider](/ja/providers/) を設定します。
5. [Daily Brief](/ja/plugins/daily-brief/) や [Webhook](/ja/plugins/webhook/) など公式プラグインを選び、読書を始めます。

## トレイとバックグラウンド動作

ウィンドウを閉じてもフィード取得は継続します。トレイ／メニューバーの `Open Dibao` で再表示し、Quit で完全終了します。

「設定 → このインスタンスについて → ログイン時にバックグラウンドで起動」は初期状態で無効です。有効にすると、ログイン時はリーダーを表示せず常駐します。手動起動やバックアップ／復元後の再起動ではウィンドウを表示します。未署名 macOS 版ではログイン項目の登録が失敗する場合があります。

## オフライン読書

Desktop はローカル DB を使い、接続がなくても保存済みの記事を開き、閲覧状態を記録できます。PWA キャッシュの有効化や保存記事数の制限は適用されません。新しい記事、未保存の外部画像、AI サービスには接続が必要です。

NAS や遠隔サーバーとの同期ではありません。別環境からのインポート、遠隔接続、多端末同期は未対応です。Web／PWA の使い方は [オフライン読書](/ja/offline-reading/) を参照してください。

## 更新

設定から更新を確認します。Windows はダウンロードと「再起動して更新」にそれぞれ確認が必要で、通常終了ではインストールしません。macOS は完全終了後、新 DMG で「アプリケーション」の Dibao を上書きします。

新しい版は移行前にデータを保存し、保存失敗時は更新を停止します。安定版がプレリリースを自動受信することはなく、旧アプリで新しいデータを直接開くこともできません。

## データとバックアップ

| システム | データルート |
| --- | --- |
| Windows | `%LOCALAPPDATA%\Dibao` |
| macOS | `~/Library/Application Support/Dibao` |

設定からフォルダーを開けます。`data` は DB、プラグインデータと鍵、`profile` はログインとクライアント状態、`backups` はバックアップです。アプリ本体と別保存され、更新、上書き、再インストール、通常のアンインストールではデータを削除しません。

「バックアップと復元」で手動保存、日時による復元ポイント選択、結果確認ができます。確認後に再起動して実行し、復元前に現状も別保存しますが、復元日以降の変更は戻ります。有効な保存がない場合、復元は無効です。

成功した更新前バックアップを直近三件保持し、手動保存と復元前スナップショットは自動削除しません。保存先は本機のみです。別媒体にも保存する場合は完全終了後にルート全体をコピーしてください。SQLite 本体のみのコピーや鍵の省略では不十分です。

## 問題への対処

- 起動できない：アーキテクチャと OS の警告を確認します。Windows ARM ネイティブ版は未対応です。
- 更新後にデータが見つからない：元のルートを使っているか確認します。使用中のディレクトリー移動や鍵の削除は避けてください。
- 既存 DB が欠落・空と表示される：残存ファイルを保ち、復元案内に従います。保護を迂回して空 DB を作らないでください。
- 更新／保存が無効：設定を保存し、データ更新の完了を待ちます。
- 旧版へ戻す：対応する完全バックアップを先に復元します。[バックアップと更新](/ja/backup-upgrade/) を参照してください。
